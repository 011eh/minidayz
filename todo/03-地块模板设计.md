# 地块模板（Block Template）设计

> 对应 `01-地图生成.md` 阶段 C（建筑实例化）的设计细化。
> 槽位引用的车/树/障碍/容器场景见 `02-环境物体场景.md`（本文的前置依赖）。
> 调研来源：`origin/others/文档/城镇生成逻辑.md`、`origin/others/文档/datajs_export/map_generation.decoded.txt`。
> 决策方式：场景化（`.tscn`）承载模板，槽位位置在编辑器画布可视化调整。

---

## 0. 核心认知（先纠正三个误区）

1. **不只是「城镇」模板，而是「地块」模板**。原版每个非空格子都由一个**模板号**展开——村庄/城市/军营/医院/消防是模板，**道路（纵/横/十字）同样是模板**，野外森林也是（但走程序散树）。命名用「地块模板」更准确。
2. **车辆不只在城镇，主要在路边**。三种道路模板都铺大量车（十字 13 辆、纵路 10 辆、横路 4 辆），地点模板里也有（医院最多 11 辆）。详见 §2。
3. **模板不止「摆对象」，还「铺地面」**。每个地块除了对象槽位，还会往地面地形层盖一块「路面足迹」（医院是大铺装、村庄是连接房子的小路）。详见 §3。

## 1. 原版架构：一个「模板号」驱动两个函数

原版**没有单一的「模板对象」**。一个地块的全部内容，由它的模板号（`t507.iv[0]`）在**两个不同函数**里分别展开：

| 函数 | 阶段 | 按模板号产出 | 内容 |
|---|---|---|---|
| `generate_location(模板号)` | 步骤6 填数据 | **对象槽位** → `t518` 数组 | 建筑/车/树/容器/特殊 |
| `create_map_location(模板号)` | 步骤8 实例化 | **① 地面足迹** → `t945` 地形层<br>**② 装饰散布** → `t221` 装饰层 | 路面铺装 / 草地杂物 |

> 即：模板号是个抽象编号，同时管「摆什么对象」「铺什么地面」「撒什么装饰」三件事，但代码上分散在不同函数。

**类型码 → 模板号**（步骤5 `generate_array_tomap`，含随机）：

| 地块类型 | → 模板号 | 备注 |
|---|---|---|
| 村庄 | `choose(9, 4, 16, 17)` | 4 套排列 |
| 城市 | `choose(6, 21)` | 2 套 |
| 军营 | `22`（部分后处理升级为 `5`） | |
| 医院 | `11` | |
| 消防站 | `15` | |
| 道路 横/纵/十字 | `13 / 12 / 14` | 道路也是模板 |
| 空地/森林 | `choose(3,1,2,8,10,1,2,8,10)` | 森林模板 `1/2/8/10` 权重翻倍，空旷草地模板 `3` 单份；走程序散布，非固定槽位，详见 §10.1 |
| 秘密地点 | `choose(23..49)` | 16 种特殊 |

## 2. 模板元素之一：对象槽位

对应原版 `t518` 每行 `[kind, code, dx, dy]`。每个槽位 4 个字段：

| 字段 | 含义 | 例子 |
|---|---|---|
| `kind` | 元素种类 | 7=建筑、6=车辆、1=树、3=特殊单体(信箱/牌子)、4=物件（按 `code` 分发，如 `code 4`=长椅，见 §9.1） |
| `code` | 资源编号，**可固定可随机** | `9` 固定 / `choose(9,10,11,12,13)` 随机色 |
| `dx, dy` | 相对 hotspot 的**像素**偏移 | `+844, +91` |

- 部分槽位**位置也带随机**：车辆 `dx = +100 + random(300)`（路边车散开）。
- **野外森林是例外**：不是固定槽位，`Repeat(16)` 在 4×4 子格程序化散树。

## 3. 模板元素之二：地面足迹（新发现，原版真实存在）

原版有一张地面地形 tilemap **`t945`**（贴图 `ground_lvl{1-4}_tilemap.png`）。`create_map_location` 阶段，**每个地点和道路都往这张图盖一块路面足迹**：

1. **填实心（tile 15）**：用 `SetTileRange` 把足迹区域刷成 tile 15（路面满铺）。形状各模板不同：
   - 医院：7 个矩形拼 L/十字形大铺装；
   - 村庄 9：13 个矩形 = 村内多条窄路（连接各房子的小径）+ 外接路口；
   - 道路：路条 + 路口。
2. **8 邻居自动地形**：扫每格，按 8 邻居是否为 tile 15（`CompareTileAt == 15`）换成边/角过渡 tile（`SetTile 0~12`），让路面与草地平滑衔接。

> **本质 = Godot `set_cells_terrain_connect`**：原版「填 15 + 邻居 autotile」就是 Godot 地形连接做的事。
> 道路和地点铺的是**同一个路面 terrain**，所以村内小路能无缝接到村外的路。
> 坐标系：足迹用 block 内 tile 偏移（17×17 格），与本项目 `BLOCK_SIZE_IN_TILE=17`、terrain 60px **完全一致，偏移 1:1 直接用**。

**现状（已实现）**：`ground.gd` 的 `render_map` 把道路 cells、各地点模板 `Footprint` 的 cells、地点朝相邻道路伸出的连接臂（`_collect_location_arms`）收进同一个 `pavement_cells` 字典，最后一次 `set_cells_terrain_connect(…, 0, 1, false)`。
模板的 `Footprint` 由 `dev_res/footprint_painter.gd`（EditorScript）从原版 `create_map_location` 的 `SetTileRange` 序列读出后绘制：路面矩形外扩 1 格、写回草地的矩形内缩 1 格以对齐两边角匹配约定；依赖邻接道路的接口臂矩形跳过，交给 `ground.gd` 生成期处理。

## 4. 建筑自身：多层自包含（不归模板管）

一栋建筑不是单图，是**多层精灵叠加**（以教堂 code 16 为例，`create_map_element` kind=7）：

```
教堂对象 = b_church_int(底座/地板, Buildings_base 层)   ← 建筑脚下那块铺装，属于建筑自己
         + b_church(主体外观)
         + 墙体碰撞(按精灵图点 w1~w4 定尺寸)
         + 阴影(Buildings_shadows)
         + 僵尸刷新点 ×N + 内部/loot
```

→ **建筑脚下的小块铺装 = 建筑自带的底座层**，与模板无关。模板只负责把整栋 `building.tscn` 摆到槽位。
→ 对应 Godot：每个 `building.tscn` 自己包含 `BaseFloor / Body / Walls / Shadow / Interior / ZombieSpawns / Loot`。这是阶段 C 的前置依赖（**建筑场景需自包含其内部**，否则城镇是空壳）。

## 5. Godot 场景化设计

把原版分散在两个函数的内容，**收进一个模板场景**（比原版整洁，且可视化）。

> 以下为**已实现**的结构，代码位于 `environment/location_template/`。

### 5.1 候选池 `SlotPool`（`slot_pool.gd`，Resource）

- `entries: Array[PackedScene]`，`pick(rng)` 等概率抽一个；重复条目即加权。
- 两种用法：共享 `.tres`（`pool/cars.tres` / `trees_town.tres` / `houses_village.tres`）；模板内单用的写成场景内 SubResource（如村庄 17 的 `Pool_church_or_brick`）。
- 同一个类也用作「地点类型 → 模板场景」池（`pool/templates_village.tres`）。

### 5.2 槽位节点 `TemplateSlot`（`template_slot.gd`，`@tool extends Marker2D`）

| 字段 | 作用 |
|---|---|
| `pool: SlotPool` | 候选场景；1 个 = 固定，多个 = 随机 |
| `position_jitter: Vector2` | 以 marker 为中心 ±jitter 的均匀随机偏移（路边车/树用） |
| `entry_offsets: Array[SlotEntryOffset]` | 按候选登记额外偏移，还原「二选一、各有坐标」的槽（村庄 17 教堂/红砖房：红砖房 `(0,-71)`） |
| `preview_index` | 编辑器内预览第几个候选的贴图（递归收集场景内 `Sprite2D` 绘制） |

- `pick(rng) -> SlotPick`：一次性决定候选场景与落点（落点依赖所选候选，不能分两次取）。
- **没有 `kind` 枚举**：槽位只关心实例化哪个场景，元素种类由场景本身决定（D1 结论）。
- 原版 code→资源映射表不再需要，槽位直接引用 `PackedScene`。

### 5.3 模板根 `LocationTemplate`（`location_template.gd` + 基础场景 `location_template.tscn`）

```
LocationTemplate (Node2D, @export category: VILLAGE/CITY/MILITARY/HOSPITAL/FIRESTATION/SECRET)
├── Footprint (TileMapLayer, tile_set = ground_terrain.tres)  ← 地面足迹，对应原版 t945 分支
└── Slots     (Node2D)                                        ← TemplateSlot 们
```

具体模板（如 `village_17.tscn`）继承基础场景。`build(rng, pavement_cells)`：
1. `Footprint.get_used_cells()` 加上本块 tile 原点后写入 `pavement_cells`，然后释放 `Footprint`；
2. 快照 `Slots` 下的 `TemplateSlot`，逐个 `pick` → `instantiate` → 设位置 → 加到 `Slots`，释放 marker。

其它：编辑器内画出 1020×1020 地块边框；F6 单独运行时自建并挂 `dev_res/location_template_preview.gd` 调试视图。

> 实例化后整个地块就是一个节点子树，满足「按 town 粒度管理/剔除」（阶段 D）。
> 设计中的 `CityGround`（城市整块地面底图）与 `VisibleOnScreenEnabler2D` 尚未加入，前者随城市模板场景一起做。

### 5.4 应用器（`environment/ground.gd`）

- 每类地点一个 `@export var xxx_templates: SlotPool`（`_template_registry()`），目前只有村庄池已赋值（仅 `village_17`）。
- `render_map`：草地基底 → 水 → `_collect_road_cells` → `render_locations`（按 `locations` 实例化模板到 `Locations` 节点下，hotspot = block × 1020px）→ `_collect_location_arms` → 一次 `set_cells_terrain_connect` → 装饰。
- `locations` 只收集 5 类地点 + 秘密地点；**道路地块和空地（野外）目前不实例化任何对象**，见 §10。

## 6. 边界划分（场景内 vs ground.gd）

| 原版「模板号产出」 | 放哪 | 理由 |
|---|---|---|
| 对象槽位（建筑/车/树/容器） | ✅ **模板场景**（`TemplateSlot`） | 固定布局，要可视化摆位 |
| 地面足迹（路面铺装形状） | ✅ **模板场景**（`Footprint` TileMapLayer） | 固定形状，画一次，应用时并入全局 terrain-connect |
| 城市整块底图 | ✅ **模板场景**（`CityGround` Sprite2D） | 城市特例 |
| 建筑内部（底座/墙/影/僵尸/loot） | 🔵 **building.tscn 自包含** | 与模板解耦 |
| 装饰散布（t221 草地杂物） | 🟡 **留 `ground.gd`**（已有 `render_decoration`） | 随机散布、非固定形状，按 block 类型撒即可 |
| 类型→模板号 choose、遍历落地、rng | 🟡 **`ground.gd` + 注册表** | 属于世界生成，与单模板解耦 |

> 原则：**「确定的东西」（对象位置、路面形状）进模板场景；「随机散的东西」（装饰）留全局**。

## 附：关键数值与坐标

- 网格 16×16，格距 `CELL = 1020px`，地块 hotspot = `block坐标 × 1020`。
- 建筑偏移用**像素绝对坐标**，原版 `dx/dy` **1:1 直接照搬**（tile=60px 已使尺度对齐）。
- **建筑锚点约定**：建筑场景根节点原点 = Inside 地板贴图底边中心（bottom-center）。原版 `dx/dy` 为旧锚点（左上）坐标，摆放时需加上该建筑的 shift 值，换算表见 `04-建筑锚点统一.md`。
- 地面足迹用 block 内 tile 偏移（17×17 格），与项目 terrain 60px 一致。
- 随机性只有两处：① 类型→模板号 `choose`；② 槽内 `choose` + 位置 jitter。骨架（格距、槽位偏移、足迹形状）完全确定。
